# reef-backend

The Rust half of the Reef store client. The QML UI (`../ui`) talks to a single CXX-Qt object (`reef/client/app/src/bridge.rs`), and that object is a thin shell over this crate. This crate does no networking of its own: the UI layer downloads the catalogue, tokens and revocation list and passes the bytes in. That keeps an HTTP stack out of the crate and every rule unit-testable.

| Module | What it does |
| --- | --- |
| `release` | Finds the installed Sailfish release. It reads `VERSION_ID` from `/etc/sailfish-release`, then `/etc/os-release`, then falls back to parsing `version` output. It **never** uses `ssu re`, which the OS updater can move ahead of the installed release (docs/plan.md, "Repository mechanics"). `native_arch()` gives the RPM architecture name. |
| `repo` | Produces the exact commands that register the `shipwright-reef` repository pinned to that release: `ssu ar shipwright-reef 'https://reefstore.app/sailfishos/5.2.0.17/%(arch)/'`, `ssu ur`, `rpm --import …`, `pkcon -p repo-set-data shipwright-reef refresh-now true`. It parses `ssu lr` into `PinState` (`Pinned`, `Missing`, `Disabled`, or `Drifted` after an OS update) and gives the repair commands for each state. `ReleaseGranularity::MajorMinor` publishes under `5.2/` instead of `5.2.0.17/` (see below). `RepoConfig::from_repo_conf` reads the installed `repo.conf` (alias, URL template, granularity, key), so the client registers and checks exactly what the installer did. |
| `catalogue` | The `catalogue.json` model, schema 1. It is published per release and arch by `tools/build/reef`. `visible(release)` returns only packages whose `tested_on` contains the exact installed release, sorted by category and then title (the list's sections); everything else is hidden. The catalogue is not signed, so `parse` refuses a licence `app_id` that is not a safe file name and a non-`https://` purchase URL, and drops a non-`https://` homepage or source. |
| `packagekit` | `PackageManager` trait (resolve, install, update, remove, get-updates, refresh one repository) and `dbus::PackageKitClient`, a zbus 5 implementation over `org.freedesktop.PackageKit`. It creates a transaction, subscribes to that transaction's signals *before* calling the method, reads `Package`, `ItemProgress`, `ErrorCode` and `PropertiesChanged` (Percentage, Status) until `Finished`, and reports progress to a callback. Signals are matched on the daemon's unique bus name as well as the transaction path (and checked again per message), so another bus client cannot forge results; a transaction silent for 10 minutes (`DEFAULT_IDLE_TIMEOUT`) fails instead of blocking. Installs and updates always set `ONLY_TRUSTED`. Removal never autoremoves and refuses when dependants exist (`allow_deps=false`). `reef_updates` keeps only updates whose package id comes from Reef's repository, so Reef never touches system packages. |
| `licences` | `LicenceStore`: one verified token file per app (mode 600, written atomically). Every app id is checked with `handoff::valid_app_id` before it becomes a path, whether it came from a token, the catalogue or QML. The revocation list and its signature are one file (`revocations.signed`), loaded and verified once per `list()`. A stored subscription token is never replaced by one for the same licence that expires sooner. The module also computes refresh-needed and holds the signed revocation list, rejecting a list older than the stored one. `EMBEDDED_KEYS` comes from `SHIPWRIGHT_LICENCE_KEYS` at build time (below) and is empty without it; an empty key set rejects every token. |
| `claim_codes` | How a licence bought on the web reaches the phone. `new_claim()` makes a claim code (128 bits from `getrandom`, 32 lowercase hex characters), `purchase_url_with_claim` adds `claim=<code>` to the purchase URL's query (before any `#fragment`), and `PendingClaims` keeps the codes not yet redeemed: one file per code in `claims/` beside the licence directory, `{"app_id", "created_at"}`, written like a token (mode 600, atomically; directory 700), at most 20, dropped after 30 days. The app redeems them during a licence refresh (`GET /v1/claims/{code}`, reef/client/app `jobs::refresh_licences`). |
| `licenced` | The licence hand-off service: `org.shipwright.Reef.Licences1.GetLicence(app_id)` returns the token `LicenceStore` holds for that app (`NotFound` if none or revoked, `InvalidAppId` for anything outside `[A-Za-z0-9._-]{1,128}` or starting with a dot). Run by the D-Bus-activated binary `shipwright-reef-licenced` (`src/bin`), which exits after `SHIPWRIGHT_REEF_LICENCED_IDLE_SECS` (default 30) idle seconds. Design and the decision not to authenticate callers: `reef/licence/README.md`, "Licence hand-off". |
| `store` | `Store<P: PackageManager>` (install by name from Reef's repository, update-all for Reef packages only, remove). `installed` and `remove` count only Reef's packages (`reef_owned`: names Reef recorded installing in its `InstallLedger`, `$XDG_DATA_HOME/shipwright-reef/installed.json`, so a disabled repository or a withdrawn build does not orphan them; else `installed:<alias>`, or a plain `installed` whose name the Reef repository also offers), so a catalogue entry naming an OS package never shows it as installed or offers to remove it. and `entries()`, which joins catalogue rows with install and update state for the UI. |

## Release granularity

The plan pins Reef to the full installed release (`sailfishos/5.2.0.17/aarch64/`), and that is the default. Chum publishes Sailfish 5.x repositories per major.minor instead: `…/chum/5.2_aarch64/` returns 200, while `…/chum/5.2.0.15_aarch64/` returns 404. Older releases such as 4.6.0.13 and 5.0.0.62 used full strings. For that reason the path component can be configured. `RepoConfig::granularity`, `REEF_RELEASE_GRANULARITY` in `reef/installer/repo.conf`, and `--granularity` in `tools/build/reef/publish-repo.sh` must agree. Whichever granularity is used, `tested_on` always holds full release strings and the client filters on the full installed release. A `5.2/` repository therefore still hides a build that was tested only on 5.2.0.17 from a phone on 5.2.0.18.

The release goes into the URL as a literal string; the architecture stays as ssu's `%(arch)`. This follows Chum: `sailfishos-chum-gui-installer`'s `%post` and `sailfishos-chum-gui`'s `src/ssu.cpp`, where the GUI replaces its release variable with a literal version when the user picks one.

## Build and test

```
cargo test -p reef-backend       # unit tests + 5 PackageKit and 3 licence hand-off D-Bus tests
cargo clippy -p reef-backend --all-targets -- -D warnings
cargo run -p reef-backend --example validate-catalogue -- catalogue.json aarch64 5.2.0.17
```

**Licence keys.** `build.rs` fills `licences::EMBEDDED_KEYS` from the build-time variable `SHIPWRIGHT_LICENCE_KEYS`, `kid:base64url` entries separated by commas, as `shipwright-licence-service public-key` prints them (for example `SHIPWRIGHT_LICENCE_KEYS=staging-k1:<key> cargo build -p reef-backend`). A malformed value fails the build, unset means no trusted key, and a release build (`--cfg release_build`) refuses key ids starting with `staging` or `test`. Changing the variable rebuilds the crate. `reef_licence::build` (reef/licence/README.md) does the parsing; device builds pass the variable through `tools/build/native/native.sh` or `tools/build/sdk/sdk.sh`.

`tests/packagekit_mock.rs` starts a private `dbus-daemon` with a generated config and serves a mock `org.freedesktop.PackageKit` on it (zbus `interface` macros, PackageKit's wire signatures). It then drives the real client against the mock. This checks the D-Bus contract: argument types, that `ONLY_TRUSTED` (0x2) goes on install and update, that the filter bitfields match PackageKit-Qt (Installed 0x4, NotInstalled 0x8, None 0x2), that signals emitted before the method reply are not lost, that progress arrives from both `ItemProgress` and `PropertiesChanged`, that `ErrorCode` plus a failed `Finished` becomes an error, that remove runs with `allow_deps=false, autoremove=false`, that only Reef updates are applied, that a `Finished` forged by another bus client is ignored, and that a silent transaction times out. If `dbus-daemon` is missing, the test is skipped with a message, except when `CI` is set, where it fails.

`tests/licenced_dbus.rs` does the same for the licence hand-off: the service in-process on a private bus (token returned, revoked and unknown apps give no token, a path-like app id is refused by client and service), no service (the client reports it unavailable), and the real `shipwright-reef-licenced` binary started by D-Bus activation from the packaged `.service` file, answering, exiting when idle (1 s in the test) and being activated again.

Dependencies: `zbus 5` (async-io, no tokio), `async-io 2` (the transaction timeout), `futures-lite 2`, `getrandom 0.4` (claim codes), `serde`, `serde_json`, `reef-licence`.

## Needs device verification

Each of these needs a real phone. They belong to Phase 0 probe 7 unless noted.

1. **Unsandboxed or helper.** Install a build with `Sandboxing=Disabled` and `/usr/share/mapplauncherd/privileges.d/shipwright-reef` (`/usr/bin/shipwright-reef,r`), copying what `sailfishos-chum-gui` ships (see `../packaging/`). Launch it from the app grid and run `Store::install` for a test package. Record whether PackageKit accepts the transaction. Then repeat with Sailjail enabled (remove `Sandboxing=Disabled`) and record the error. If the unsandboxed launch fails too, the fallback is a privileged helper in `reef/helper`.
2. **PackageKit wire values on Sailfish.** Sailfish's PackageKit (zypp backend) version is not recorded here. Run `pkcon backend-details` and `busctl --system introspect org.freedesktop.PackageKit /org/freedesktop/PackageKit`, and create a transaction and introspect it. Confirm that `Resolve(tas)`, `InstallPackages(tas)`, `RemovePackages(tasbb)`, `GetUpdates(t)`, `RepoSetData(sss)` and the `Package(uss)`, `ItemProgress(suu)`, `Finished(uu)` signatures match what `packagekit/dbus.rs` expects.
3. **Package id data field.** Run `pkcon -p resolve shipwright-reef` and `pkcon -p get-updates` with the Reef repository added. Confirm that available and update package ids end in `;shipwright-reef`, and that installed ones end in `;installed` or `;installed:shipwright-reef`. Also run `pkcon -p resolve <installed Reef app>` with no filter and confirm it lists both the installed copy and the repository's: `reef_owned` (installed state and removal) depends on that. `reef_updates` and `resolve_installable` depend on the data field.
4. **Signed-only installs.** Publish one unsigned test RPM to a test Reef repository and call `install`. PackageKit must refuse it because of `ONLY_TRUSTED`. Record the error code.
5. **`ssu lr` format.** Compare the output of `ssu lr` with the fixture in `repo.rs` (`- <alias> ... <url>` under `Enabled/Disabled repositories` headers). Check whether ssu shows `%(arch)` expanded or literal (`pin_state` accepts both).
6. **ssu URL substitution.** After `ssu ar shipwright-reef 'https://reefstore.app/sailfishos/5.2.0.17/%(arch)/'` and `ssu ur`, run `ssu lr` and `cat /etc/zypp/repos.d/*shipwright-reef*`. The URL must read `…/5.2.0.17/aarch64/` with the release literal (not changed by `ssu re`) and the arch expanded.
7. **Drift after an OS update.** Update the phone (for example 5.2.0.17 to 5.2.0.18), open Reef, and check that the repository state is `Drifted` and that Repair re-pins it to the new release.
8. **`ssu er`.** Confirm that `ssu er <alias>` re-enables a disabled repository; it is used for the `Disabled` repair.
9. **Release file.** Record `cat /etc/sailfish-release /etc/os-release` and `version` on 5.2.0.x and on 5.1.0.x. Check that `release::parse_release_file` and `parse_version_output` read them.
10. **Licence hand-off.** Decided and implemented (`licenced`, `reef/licence/README.md`); its device checks are listed there.
