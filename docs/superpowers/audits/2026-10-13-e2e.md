## 2. The host e2e harness

`tests/e2e/run.sh` (README alongside) runs the real `marathon-shell-bin`
under Xvfb at the 390×844 design canvas, `MARATHON_FORCE_DPI=160`, software
Quick backend, own HOME/XDG dirs, own session bus and AT-SPI bus, with the
real apps launched through `marathon-app-runner`. Input is xdotool (taps,
swipes, the pill gestures, long-presses, the on-screen keyboard). Checks use:

- the shell log (`MARATHON_DEBUG=1`): surface mapping, notification model,
  alarm manager, settings writes, runner `--route`;
- the shell's D-Bus API (`Security1.GetState`, `Navigation1`, `Alarm1`) and
  `org.freedesktop.Notifications`;
- the accessibility tree (`tests/e2e/a11y.py`): what is showing, headings,
  text-field contents, and the screen position of anything to tap by name.

Every step writes a screenshot (`$E2E_OUT/shots/NN-step.png`); a failing
check also dumps the accessibility tree next to it.

### Why the shell said "Session bus not connected"

`shell/main.cpp:410-412` unconditionally rewrites `DBUS_SESSION_BUS_ADDRESS`
to `unix:path=$XDG_RUNTIME_DIR/bus` (a workaround for AT_SECURE respawns on
the device). Under `dbus-run-session` the bus is at a random address, so the
shell connected to a socket that did not exist, while everything else in the
session used the real bus. The harness now starts the bus exactly at
`$XDG_RUNTIME_DIR/bus`, as on the device. The shell code was left alone; if
this bites a developer again the fix is to only derive the address when the
variable is unset.

Other isolation the harness needed:

- **Unix socket paths are capped at 108 bytes**: the runtime dir is a short
  `mktemp -d /tmp/me2e-XXXXXX`.
- **The bus has no service directories.** With the default session config,
  the App Store's `Qt.openUrlExternally("marathon-store://refresh-state/all")`
  activated the host's xdg-desktop-portal, which opened **the host's Firefox**
  on the test display. `xdg-open` is also stubbed and logs to
  `xdg-open.log`.
- **Binaries are copied before a run** (shell, runner, libMarathonCore,
  libMarathonServices): other agents relink `build-tests` all night, and one
  run died on `Permission denied` mid-link.
- `MARATHON_FORCE_VKB=1`: the host's real keyboard is detected over evdev and
  otherwise suppresses the OSK.
- `KEEL_THEME_ICON_DIRS` points at the built icon theme, or every Keel icon
  is missing in the apps.
- Hardware keys typed into the Xvfb window reach the shell's own fields but
  not app (Wayland) surfaces, so app typing goes through the OSK.

The shell still uses the host's **system** bus (NetworkManager, BlueZ,
ModemManager, UPower, logind): the OOBE Wi-Fi page lists the house networks,
Bluetooth scans real devices, a ringing alarm takes a real logind inhibitor.
The flows never touch a radio switch or suspend.

## 5. Bugs found, not fixed (owned by agents working in those files tonight)

**A. Music does not start (P0).** Runner error:
`MusicApp.qml:12:1: "MarathonApp.Music" is ambiguous. Found in qrc:/qt/qml/MarathonApp/Music/ and in qrc:/qt/qml/MarathonApp/Music/`.
`apps/music/MusicApp.qml:8` imports its own module (`import MarathonApp.Music 1.0`, added in bcfe2214); the `import "pages"` directory import at line 12 is redirected by `pages/qmldir` (`prefer :/qt/qml/MarathonApp/Music/`) to the same module, and Qt 6.11 rejects the second import. **Fix: delete line 8** — MusicApp.qml is in the module, so `MprisPlayer`/`Artwork` are already in scope. Verified on a scratch build: with the line removed Music maps a surface; with `import MarathonOS.Shell` removed instead it still fails. Qt version on the device should be checked; the app suites pass because they load from the source tree.

**B. Settings: permission "phone" shows as raw `phone`** in App info (Phone, Messages). `apps/phone/manifest.json:8` and `apps/messages` declare `phone`; the runner treats it as `telephony` (`tools/marathon-app-runner/main.cpp:1128`), but `apps/settings/SettingsLogic.js:262` `permissions` has no `phone` key (nor `secret-service`, used by Mail). Fix: add `phone: { title: qsTr("Phone"), description: qsTr("Make and answer calls") }` (and a `secret-service` entry).

**C. Settings search: the "No matching settings" placeholder is drawn over the search field** while the keyboard is up (`apps/settings/pages/MainPage.qml:192`, screenshot `osk-typed`). The ViewPlaceholder centres in the shrunken flickable. Fix: give it a `verticalOffset` that keeps it below the search field, or anchor it under the header.

**D. App Store opens `marathon-store://refresh-state/all` through the desktop URL handler on every start** (`apps/store/models/StoreBackend.qml:984`). On the host that launched Firefox. On the device it relies on a registered `x-scheme-handler/marathon-store`; the store handler is being moved to Rust tonight (`crates/marathon-store-handler`) — whoever finishes that should make sure the handler is registered in the image, or every Store launch opens the Browser.

**E. Switcher card titles elide far too early** ("Not…", "Me…" with room to spare), `shell/qml/components/TaskCard.qml:533-540`: the label column is `card − icon − close button − 2×spacing`, which at the switcher's card width leaves ~60 px. Being reworked by the shell-visuals agent (MarathonTaskSwitcher.qml in flight).

**F. Dock: the camera ring overlaps the page-indicator dashes** on the 390-wide canvas (`shell/qml/components/MarathonBottomBar.qml`, camera shortcut at :208). Shell-visuals agent.

**G. App menu is a boxed black card** (`shell/qml/components/AppContextMenu.qml:38-45`, `radius`, 0.85 black fill, border) rather than a Silica ContextMenu — at odds with the "no boxed surfaces" rule. Shell-visuals agent.

**H. Phone dialer: "No SIM or modem" was drawn as "… SIM or modem"** in one run (fade truncation from the left) — `apps/phone` dialer status label; appears when the label width is computed before layout. Low.

**I. OOBE passcode keypad jumps up** when the step changes from "Create a passcode" (two-line subtitle) to "Confirm passcode" (one line) — `shell/qml/components/MarathonOOBE.qml` passcode page. Low.

**J. Accessibility: the home grid stays "showing" behind the setup wizard**, so a screen reader can walk into the home screen during first-run. Low.

Observations, not bugs:
